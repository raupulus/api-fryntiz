## 1 GENERALIDADES

### 1.1 ¿Qué es Aemet OpenData?
🔹 Es un servicio que provee fundamentalmente datos meteorológicos y climatológicos elaborados por Aemet, así como diversos productos tanto gráficos como textuales.
🔹 Es de libre uso y gratuito.
🔹 La descarga se puede hacer de dos formas: A través del acceso general , que de forma guiada, se recomienda para extraer pocos ficheros y de forma esporádica.
A través del acceso para desarrolladores , está recomendado para expertos, que mediante programación, permite descargas voluminosas de información de forma automatizable.

🔹 Para descargas manuales se debe entrar al servicio por el acceso general y para las automáticas por el acceso desarrolladores.

### 1.2 ¿Qué información me puedo descargar?
🔹 Datos de observación, radiación y contaminación de fondo.
🔹 Imágenes de radar, mapas de rayos y productos derivados de satélite.
🔹 Climatologías, valores normales y otros productos climatológicos.
🔹 Predicciones normalizadas en texto, predicciones específicas, predicciones marítimas.
🔹 Mapas significativos, de análisis y previstos.
🔹 Avisos de fenómenos meteorológicos adversos e índices de incendios.

### 1.3 ¿Cuáles son las condiciones de uso y reutilización de la información que me descargue?
Puede consultarse en la nota legal: nota legal

### 1.4 ¿Qué información me puedo descargar?
Se pretende poner a disposición de los ciudadanos todos los productos de libre acceso y gratuitos aprobados en la resolución de precios públicos de AEMET actualmente en vigor. También están disponibles los datos obtenidos por Aemet en el marco del convenio de colaboración entre la Agencia Estatal de Investigación y la Agencia Estatal de Meteorología con respecto a las actividades españolas en la Antártida .
Aemet elabora otros productos y servicios que por diferentes motivos no estarán disponibles en Aemet OpenData. Estos productos y servicios pueden ser solicitados a través de la sede electrónica de AEMET .

### 1.5 ¿Por qué algunos productos elaborados por Aemet no son de acceso libre y gratuito?
La política de datos de Aemet, aprobada por el Consejo Rector de la Agencia, según fija su estatuto , establece el conjunto de datos que se consideran abiertos (libres y gratuitos). Otros llevan un coste marginal asociado o requieren adaptaciones específicas y, por ello, se suministran bajo petición. Además, ciertos productos se elaboran de acuerdo con los requisitos legales de determinados sectores, por lo que son de uso restringido.

### 1.15 ¿Qué significan los códigos de estado HTTP devueltos por la API?
La API puede devolver diferentes códigos HTTP para indicar el resultado de una petición.
200 - Operación realizada correctamente
La petición se ha procesado correctamente y la respuesta contiene la información solicitada.
Ejemplo de respuesta JSON

{
"descripcion" : "exito",
"estado" : 200,
"datos" : "https://opendata.aemet.es/opendata/urldatos",
"metadatos" : "https://opendata.aemet.es/opendata/urlmetadatos"
}

401 - No autorizado
La API Key no es válida, ha expirado o no se ha incluido correctamente en la petición.
Ejemplo de respuesta JSON

{
"descripcion": "La API Key ha expirado. Genere una nueva API Key.",
"estado": 401
}

403 - Acceso denegado
La API Key es válida, pero no dispone de permisos para acceder al recurso solicitado.
Ejemplo de respuesta JSON

{
"descripcion": "No dispone de permisos para acceder al recurso solicitado.",
"estado": 403
}

404 - Recurso no encontrado
El recurso solicitado no existe o no se encuentra disponible.
Ejemplo de respuesta JSON

{
"descripcion": "Recurso no encontrado.",
"estado": 404
}

429 - Límite de uso superado
Petición que supera alguno de los límites del servicio (Límite de peticiones o caudal por minuto excedido para este usuario):
Ejemplo de respuesta JSON

{
"descripcion": "Se ha superado el límite de peticiones permitido.",
"estado": 429
}


## 2 Clave de acceso – API Key

### 2.1 ¿Qué es la API Key?
🔹 Es una clave que sirve para acceder al servicio Aemet OpenData, tanto como usuario general (descargas manuales), como para aplicaciones automáticas (programadores).
🔹 Las claves solicitadas a partir del día 13 de septiembre de 2017 a las 11:00 horas, tenían validez indefinida que caducarán el próximo 15 de octubre de 2026.
🔹 Se recomienda guardar la clave en el correo electrónico o en un fichero para poder copiarla cada vez que se necesite.

### 2.2 ¿Por qué este servicio requiere una clave de acceso?
Es una medida de control para garantizar el correcto funcionamiento del servicio. La clave permite aplicar mecanismos de protección y gestión del uso, incluyendo límites sobre las peticiones realizadas. El objetivo es evitar situaciones de sobrecarga y garantizar que el servicio se preste de forma adecuada y no discriminatoria para todos los usuarios.

🔹 El proceso puede durar unos minutos, por lo que es aconsejable esperar un poco.
🔹 Si el problema persiste, puede deberse a que introdujera una dirección de correo no válida. Repita el 2.3 proceso de solicitud de clave , asegurándose que escribe correctamente el e-mail donde quiere recibir el API Key.

### 2.5 No me funciona la clave
Puede solicitar otra nueva siguiendo los pasos indicados en 2.3 ¿cómo se solicita la clave?

### 2.6 ¿Puedo solicitar más de una clave de acceso?
Si. Con la misma dirección de correo puede solicitar más de una clave de acceso. Esto facilita el mantenimiento de procesamientos automatizados de datos de Aemet OpenData.

### 2.7 ¿Se requieren datos de carácter personal para utilizar el servicio?
No. Sólo se requiere proporcionar el correo electrónico para recibir la clave de acceso. La dirección del correo electrónico no se almacena en ningún fichero ni base de datos externa.

### 2.8 ¿Qué ocurrirá con las API Keys antiguas que no tienen fecha de expiración?
⚠️ A partir del 15 de octubre de 2026 , las API Keys emitidas sin fecha de expiración dejarán de ser aceptadas por la API.

Si su aplicación utiliza una de estas API Keys, deberá renovarla u obtener una nueva antes de esa fecha para evitar errores de autenticación (401 Unauthorized) . Las API Keys emitidas actualmente con una fecha de expiración válida no se verán afectadas por este cambio.

### 2.9 ¿Cuánto tiempo es válida una API key?
ℹ️ Las API Keys deben renovarse cada 3 meses desde su generación.

Antes de que caduque una clave, puedes generar una nueva desde el apartado de Obtención de API Key y actualizarla en tus aplicaciones o scripts para seguir utilizando el servicio con normalidad.
🔹 La validez de cada clave es de 3 meses.
🔹 Puedes generar una nueva clave antes de que expire la actual.
🔹 No existe límite en el número de renovaciones.

### 2.10 ¿Qué ocurre cuando una API key caduca?
⚠️ Cuando una API key alcanza su fecha de caducidad deja de ser válida y las peticiones realizadas con ella serán rechazadas.

El servicio devolverá una respuesta similar a la siguiente:
Ejemplo de respuesta JSON

{
"descripcion": "La API Key ha expirado. Genere una nueva API Key.",
"estado": 401
}

Simplemente deberás generar una nueva API key y actualizarla en las aplicaciones, scripts o sistemas que la utilicen.
🔹 La clave caducada deja de funcionar.
🔹 El acceso a los datos sigue disponible, pero será necesario generar una nueva API key para continuar utilizando la API.
🔹 No es necesario realizar ningún trámite adicional.

### 2.11 ¿Cómo obtengo una nueva API key?
Puedes generar una nueva API key siquiendo los pasos que se indica en 2.3 ¿cómo se solicita la clave? en cualquier momento.
El proceso es rápido y está diseñado para que puedas sustituir la clave anterior con el menor impacto posible en tus aplicaciones.
🔹 Accede al apartado “Obtención API Key” de la pantalla de inicio .
🔹 Actualiza la configuración de tus aplicaciones o scripts. Se recomienda realizar la sustitución antes de que la clave actual caduque.
Así evitarás interrupciones en el servicio.

### 2.12 ¿Por qué las API keys tienen fecha de caducidad?
La renovación periódica de las API keys ayuda a mejorar la seguridad y la gestión del servicio.
Esta medida contribuye a reducir el impacto de posibles usos indebidos y favorece una utilización más equilibrada de los recursos disponibles.
🔹 Mejora la seguridad de las credenciales.
🔹 Reduce el riesgo asociado a claves antiguas o expuestas.
🔹 Ayuda a mantener un servicio estable para todos los usuarios.
⚠️ si una API key caduca, bastará con generar una nueva para continuar utilizando la API.

### 3.4 ¿Qué son los metadatos y para qué sirven?
En el ámbito de Aemet, el término metadato se refiere a toda información acerca de los datos y productos meteorológicos o climáticos que elabora, y que sirve para entender su contenido, garantizando así su correcta utilización. En el caso concreto del servicio Aemet OpenData, los metadatos contienen las características principales del fichero descargado: quién lo elabora, cada cuánto tiempo se prepara, qué contiene y su formato, además de información sobre los campos de datos (variable meteorológica, unidad de medida, etc.). También se especifica el copyright y las condiciones de uso mediante la nota legal. Aemet facilita los metadatos en castellano.

### 3.5 ¿Qué es el formato JSON?
ℹ️ JSON (JavaScript Object Notation) es una estructura para intercambiar datos, que nació como una alternativa a XML.

🔹 La unidad básica de intercambio de información (objeto JSON) recibe el nombre de elemento de datos y queda delimitado por llaves { … }.
🔹 Cada elemento de datos JSON contiene pares de elementos "nombre": "valor". Los tipos de valores que podemos encontrar en JSON son los siguientes:
🔹 Un número (entero o float)
Un string (entre comillas simples)
Un booleano (true o false)
Un array (entre corchetes [] )
Un objeto (entre llaves {})
Null

🔹 Una de las mayores ventajas que tiene el uso de JSON es que puede ser leído por cualquier lenguaje de programación . Por lo tanto, puede ser usado para el intercambio de información entre distintas tecnologías. Su fácil uso en javascript ha generado un gran número de seguidores de esta alternativa.
🔹 Existen muchas utilidades online que transforman el formato JSON a CSV, XML, etc. y viceversa (de CSV, XML)
Puede encontrar más información en el Sitio oficial de JSON: https://json.org ( https://www.json.org/json-es.html , en castellano).

## 4 ACCESO DESARROLLADORES

### 4.1 ¿Qué contiene el acceso para desarrolladores?
Este acceso dispone de tres apartados:
🔹 Documentación Aemet OpenData. HATEOAS : Contiene documentación dinámica sobre el servicio Aemet OpenData y autodescubrimiento HATEOAS. Para cada tipo de producto descargable a través de este servicio, se facilitan los productos concretos disponibles, las operaciones a realizar y los posibles mensajes https según sea el resultado de la consulta.
🔹 Ejemplos de programas cliente : Facilita un conjunto de programas cliente ejemplo en diferentes lenguajes de programación.
🔹 Aemet Codegen : Es una aplicación que genera de manera automática programas cliente de Aemet OpenData, para los lenguajes de programación más utilizados en la comunidad de desarrolladores (no disponible en la actualidad).

### 4.2 ¿En qué lenguajes están programados los ejemplos cliente del acceso para desarrolladores?
Se ofrecen ejemplos en los siguientes lenguajes de programación: Curl, Java, Python, PHP, Ruby, HTTPS, C, C#, Go, JavaScript, NodeJS, Objective-C, OCame, Shell, Swift.

### 4.3 No encuentro ejemplos en lenguaje Fortan, Matlab, R o Mathematica.
No se facilitan programas en esos lenguajes, pero puede desarrollarlo partiendo de alguno similar (C, Python, etc.).

### 4.4 ¿Para qué sirven los programas ejemplo?
Los ejemplos de programas cliente sirven para facilitar la realización de procesos automáticos de descarga de datos y productos disponibles en el servicio Aemet OpenData.

### 4.5 ¿Está limitado el número de conexiones?
Sí. Para garantizar la estabilidad y disponibilidad del servicio se aplican límites de uso sobre las peticiones realizadas a la API.
Estos límites ayudan a evitar situaciones de sobrecarga, promover un uso equilibrado de los recursos disponibles y garantizar una experiencia adecuada para todos los usuarios.
🔹 Existen límites de uso aplicados a distintos niveles del servicio.
🔹 Existe un límite individual general para toda la API de 40 consultas por minuto.
🔹 Determinados recursos o funcionalidades pueden disponer de restricciones adicionales de uso.
🔹 Cuando se supera algún límite, las peticiones podrán ser rechazadas temporalmente mediante una respuesta HTTP 429 hasta que vuelva a permitirse el acceso.

### 4.6 ¿Por qué existen límites de uso y caducidad de las API Keys?
Las limitaciones de uso y la caducidad de las API Keys tienen objetivos diferentes y complementarios.
🔹 Los límites de uso ayudan a prevenir sobrecargas y a garantizar la disponibilidad del servicio.
🔹 La caducidad de las API Keys contribuye a mejorar la seguridad y el control de las credenciales.
🔹 Los límites de uso controlan el consumo de recursos, mientras que la caducidad controla la validez de las credenciales de acceso.
Ambas medidas ayudan a mantener un servicio estable, seguro y accesible para todos los usuarios.
